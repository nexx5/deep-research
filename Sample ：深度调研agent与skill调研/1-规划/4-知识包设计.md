# 知识包设计：深度调研agent与skill调研

> 本文件在调研前置准备阶段生成。它定义本项目知识包如何承载持续积累、多轮补充调研、独立分析、对话讲解、报告生成、跨项目对比和后续扩展。

## 1. 知识包目标

- **核心用途：** 沉淀"深度调研服务生态"的结构化知识——各方案的能力/架构/工作流/成本/开放度/局限、生态内方法/技术流派与趋势；支持持续积累、多轮补充调研、独立分析、对话讲解、报告生成、跨项目对比与扩展。**定位为客观生态观察**：如实记录与横向对比，不产出改进方向建议；与自有平台的对比由最终知识分析自然得出（本知识包作为其输入，不承载该对比本身）
- **报告支持：** 生态横向对比报告（客观观察：开源 vs 付费、能力矩阵、架构/工作流模式、成本/开放度/局限对照、方法流派与趋势）+ 生态证据与缺口说明报告
- **对话支持：** 分析员基于知识包回答方案对比、场景适配、生态格局/流派/证据对照类深度问题
- **分析支持：** 独立分析"某能力由哪些架构组件支撑""哪些局限是生态共性问题""各流派特征差异"等派生问题
- **对比支持：** 生态内方案按 6 对比锚点（能力/架构/工作流/成本/开放度/局限）横向对比；未来可与其他工具生态调研项目复用对比维度体系。本平台仅作为最终知识分析的可选锚点之一，不在本调研采集范围内
- **扩展支持：** 生态迭代快，新方案/新版本通过补充调研接续，只增不改既有断言（新信息 supersede 旧断言时走仲裁）

## 2. 研究对象与知识对象类型

- **research_type：** 技术调研（副轴：生态方法流派观察/市场商业）
- **主要知识对象：**
  - 方案/产品（开源框架、开源 skill、付费服务、agent 框架内置能力）
  - 能力维度（多源检索、深度追问、报告生成、证据引用、知识复用）
  - 架构与工作流（agent loop、规划器、检索器、记忆、工具、报告组装）
  - 方法/技术流派与趋势（论文驱动 vs 工程驱动、agent loop vs 静态流程）
  - 成本/开放度/局限（定价、API、自托管、许可证、失败场景）

## 3. 图谱节点类型

> 按本项目动态设计，不要机械套用模板。

| 节点类型 | 含义 | 例子 | 是否必需 |
|---|---|---|---|
| solution | 方案/产品 | deep-research 开源复刻、STORM、ChatGPT Deep Research、Genspark、Manus、hyperresearch | required |
| solution_category | 方案类别 | 开源框架 / 开源skill / 付费服务 / agent框架内置能力 | required |
| capability | 能力 | 多源检索、深度追问、报告生成、证据引用、知识复用 | required |
| architecture_component | 架构组件 | agent loop、规划器、检索器、记忆、工具调用 | required |
| workflow_stage | 工作流阶段 | 问题拆解、搜索规划、迭代检索、追问、报告组装 | required |
| method_stream | 方法/技术流派 | 论文驱动 vs 工程驱动、agent loop 流派、静态流程流派 | required |
| output_form | 输出形态 | Markdown 报告、HTML、带引用长文 | optional |
| pricing | 定价/成本 | 订阅价、API 用量、自托管资源、代理成本 | required |
| openness | 开放程度 | API 可用性、自托管、许可证、数据可导出 | required |
| limitation | 局限 | 失败场景、不可靠点、来源质量、深度限制 | required |
| own_platform | 本平台 | 调研管理平台（状态机+证据链+知识底座）——仅作最终知识分析可选锚点，本调研不采集本平台 vs 生态对比 | optional |
| comparison_dimension | 对比维度锚点 | 能力/架构/工作流/成本/开放度/局限 | required |
| evidence | 证据/来源 | 官方文档、GitHub、专业评测、社区反馈、论文 | required |

## 4. 图谱边类型

| 边类型 | 起点 | 终点 | 含义 | 是否必需 |
|---|---|---|---|---|
| belongs_to | solution | solution_category | 方案属于某类别 | required |
| has_capability | solution | capability | 方案具备某能力 | required |
| uses_architecture | solution | architecture_component | 方案采用某架构组件 | required |
| has_workflow | solution | workflow_stage | 方案工作流包含某阶段 | optional |
| outputs | solution | output_form | 方案输出形态 | optional |
| priced_at | solution | pricing | 方案定价/成本 | required |
| has_openness | solution | openness | 方案开放程度 | required |
| has_limitation | solution | limitation | 方案存在某局限 | required |
| compared_with | solution | solution | 方案间按对比维度比较（本调研采集范围；不采集 solution→own_platform，由最终知识分析派生） | required |
| belongs_to_stream | solution | method_stream | 方案所属方法/技术流派（客观归类） | required |
| opposing / coexist | capability / claim | capability / claim | 官方声称 vs 社区实测冲突 / 互补 | optional |

## 5. 必须建立的链/图

| 链/图 | 目标 | 最低完成标准 |
|---|---|---|
| 竞品差异链 | 同类方案（开源组/付费组）按 6 对比锚点横向对比（客观差异陈述） | 每组 ≥4 方案，6 锚点均有对比边 |
| 能力-架构映射链 | 能力 → 支撑该能力的架构组件 | 核心能力（多源检索/深度追问/报告生成）均有架构支撑说明 |
| 方法流派链 | 方案 → 所属方法/技术流派 → 流派特征（客观归类，不做优劣判断） | 主流派均有代表方案与特征证据 |
| 方案类别覆盖图 | 4 类方案均有代表方案节点 | 开源框架/skill/付费/内置能力各 ≥2 |
| 能力矩阵覆盖图 | 能力 × 各方案覆盖 | 5 大能力 × 全部方案均标注有无/声明/已验证 |
| （可选，由最终知识分析派生）平台定位对比链 | 本平台 vs 生态方案——不在本调研采集范围，仅作为最终知识分析的锚点占位 | 不设最低完成标准，不进入本调研完成判定 |

## 6. 核心问题清单

知识包完成后必须能回答：

1. 深度调研生态中开源框架/skill 与付费服务各有哪些代表方案，按产品形态如何归类?
2. 各方案的能力边界（多源检索/深度追问/报告生成/证据引用/知识复用）与架构（agent loop/规划器/检索器/记忆/工具）、工作流的关键差异是什么?
3. 各方案的成本结构、输出形态、开放程度（API/自托管/许可证）与已知局限（失败场景/不可靠点）是什么?
4. 生态内存在哪些方法/技术流派（论文驱动 vs 工程驱动、agent loop vs 静态流程等）?各流派的代表方案、特征与趋势是什么?
5. 官方声称 vs 独立验证（专业评测/社区反馈/论文）的差异集中在哪些维度?哪些结论可信度高、哪些是证据缺口?

暂时可能无法回答但需要记录的问题：

1. 各方案的真实内部实现细节（闭源服务架构不公开，只能基于文档与逆向/实测推断）
2. 各方案在长尾/极端场景下的成功率（公开数据有限，需标注证据缺口）

## 7. 应用能力要求

### 7.1 对话能力

- 能支持的深度问题：
  - 某两个方案在 X 维度（能力/架构/成本/开放度/局限）上如何对比，各自适用什么场景?
  - 深度调研工具生态的整体格局、产品形态分类、方法流派与趋势是什么?
  - 官方声称与独立验证/社区口碑在哪些方面存在差异（证据对照）?
- 不能只靠报告回答，必须可追溯到知识包节点/边/链（solution→capability/limitation/method_stream）。

### 7.2 报告能力

- 默认报告类型：概貌性 Markdown 报告
- 可扩展报告类型：深度报告/技术报告/对比报告/生态观察报告/图文HTML
- 报告正文默认不暴露内部ID、置信度标记或采录编号。
- **本调研不产出"改进方向建议/选型推荐"类报告**；本平台 vs 生态的对比由最终知识分析阶段产出。

### 7.3 对比能力

| 对比锚点 | 用途 | 未来可比较对象 |
|---|---|---|
| 能力维度（多源检索/深度追问/报告生成/证据引用/知识复用） | 生态能力矩阵（客观标注） | 其他 agent/工具生态调研项目 |
| 架构维度（agent loop/规划器/检索器/记忆/工具/状态机） | 架构模式归类与差异分析 | 生产级 Agent 框架工程调研等既有项目 |
| 工作流维度（拆解/规划/检索/追问/组装） | 工作流模式观察 | 生态新方案/新版本 |
| 成本与开放程度（定价/API/自托管/许可证） | 成本与开放度客观对比 | 后续工具选型决策（由用户/分析员按需执行） |
| 证据与知识管理（证据链/可追溯/冲突仲裁/知识复用） | 生态客观维度观察 | 本平台 vs 生态对比——由最终知识分析产出（本调研不采集） |

### 7.4 扩展能力

- 后续补充调研应优先补：
  - 生态新方案/新版本（采集时记录版本与时间，新断言经仲裁 supersede 旧断言）
  - 各方案实测成功率/深度表现（需统一评测基准的独立评测）
  - 付费服务定价变动与套餐结构
- 新资料进入后应更新：
  - source_registry
  - graph.nodes
  - graph.edges
  - question_index
  - coverage_map

## 8. 完成/饱和检查

- [x] `project_knowledge_schema` 已写入 knowledge-pack。
- [ ] 核心节点类型已覆盖（solution/capability/architecture/limitation/method_stream 均存在）。
- [ ] 核心边类型已覆盖（has_capability/uses_architecture/has_limitation/compared_with/belongs_to_stream 均建立）。
- [ ] 必须链/图已建立（竞品差异链、能力-架构映射链、方法流派链、能力矩阵覆盖图）。
- [ ] 核心问题进入 `question_index.can_answer`。
- [ ] 未能回答的问题进入 `question_index.cannot_answer_yet`。
- [ ] 核心节点、边、主张均有证据引用（官方参数 + 至少 1 类交叉来源）。
- [ ] 明确可支持的报告、对话、对比和扩展能力。
- [ ] 本调研未采集"本平台 vs 生态"对比内容与改进方向（该对比由最终知识分析产出）。

# 任务总规划：深度调研agent与skill调研

> 项目配置见 `project.config.md`，运行状态见 `run-state.md`

## 目标

> 与 `project.config.md#objectives` 四问对齐：本段是 objectives 在规划文件的人类可读展开。不写"工艺"（属 config 工艺段）。

调研当前可用的"深度调研服务"生态——分【开源框架/skill】与【付费服务】两类，客观收集并横向对比各自的能力、架构、工作流、成本、输出形态、开放程度与局限，观察生态内的方法/技术流派与趋势。**定位为客观生态观察**：以"看"为主、客观收集证据，不做改进方向建议。与"本项目（调研管理平台：状态机管控 + raw/采录/分析/知识包证据链 + zhishibao 知识底座）"的对比不写入调研任务，由最终知识分析自然得出。
- **服务对象：** 用户本人（深度调研平台维护者/使用者，首要服务对象）
- **交付物：** 生态横向对比知识包（可复用/可追溯/可持续扩展）+ 生态横向对比报告（客观观察，无改进建议）+ 对比维度体系（能力/架构/工作流/成本/开放度/局限六维）
- **重点场景：** 生态理解与对外汇报 / 工具框架参考依据（客观事实，不产出推荐） / 最终知识分析锚点（本平台对比由知识分析自然得出）

## 关键决策记录

| 决策 | 理由 |
|------|------|
| research_type=技术调研 + 副轴市场商业/方法流派观察 | 研究对象是技术产品生态，定位为客观生态观察：不产出选型/改进建议 |
| 付费/开源按产品形态归类而非收费与否 | 开源复刻与闭源商业服务可能同名重叠，避免断言边界混乱 |
| 本平台对比不写入调研任务 | 用户确认新定位：以"看"与客观收集为主，本平台对比由最终知识分析自然得出 |
| 生态调研复用技术选型采集字段模型（去推荐列） | scenarios/ 无"生态调研"专用策略文件，复用技术选型字段模型但只客观采集不产出推荐结论 |
| 性能/评测数据必须记录测试条件 | 生态评测基准不统一，防止不可比指标误导结论 |

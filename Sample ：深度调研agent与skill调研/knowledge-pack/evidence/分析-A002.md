## summary

本条证据源为 LangChain 团队开源的 Open Deep Research（langchain-ai/open_deep_research，替代原 404 死链来源）。该项目是深度调研 agent 的开源代表实现：基于 LangGraph 编排，采用 Scope→Research→Write 三阶段流程，研究阶段用 supervisor 多 agent 架构把任务拆解为独立子主题并行派发给多个研究子 agent（每个子 agent 在隔离上下文内做工具调用循环），子 agent 完成后用压缩模型清理 findings（保留逐字信息与来源引用），最后由单一 LLM 一次性生成与用户同语言的 Markdown 长报告（编号引用+Sources 段）。核心设计主张：多 agent 只用于研究不用于写作、上下文工程缓解 token 膨胀、supervisor 按需调节研究深度、无内置长期记忆（官方列为待解决 open question）。作为"深度调研服务生态"开源组的 solution 节点证据，其价值在于完整呈现了主流的开源多 agent 深度调研架构与成本/评测基线。

## characteristics

- 开源（MIT），可自托管
- LangGraph 图编排架构
- supervisor 多 agent + 并行子 agent
- 三阶段工作流（Scope-Research-Write）
- 工具调用循环（ReAct 风格）
- 多源检索（Tavily/原生web search/MCP工具）
- 上下文工程（brief压缩+findings压缩）
- 证据编号引用 + Sources 段
- 报告 one-shot 生成
- 高可配置（模型/并发/迭代上限）
- 无长期记忆（官方局限）

## opposing_to

- 与"单 agent 深度调研"流派对立：本文主张多子主题场景单 agent 上下文会膨胀，应隔离上下文并行；最简实现（dzhng/deep-research）用单 agent 连续深化，两派在"是否需要多 agent"上立场相反
- 与"多 agent 并行写报告"做法对立：本文用第一手教训反对并行写报告（报告 disjoint），而其他方案可能仍用并行写报告换取速度
- 与"依赖自建检索/抓取管道"方案对立：本文默认走商业搜索 API（Tavily）而非自建检索，在检索通道策略上不同
- 与"内置长期记忆/知识复用"方案对立：本文当前无长期记忆机制，官方将之列为待办，与该类方案存在能力差

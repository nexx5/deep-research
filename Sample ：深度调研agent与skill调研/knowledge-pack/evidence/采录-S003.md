# 采录-S003：STORM（stanford-oval/storm）

## 摘要

STORM（Synthesis of Topic Outlines through Retrieval and Multi-perspective Question Asking）是斯坦福 OVAL 实验室维护的开源 LLM 知识策展系统（Python，MIT，v1.1.0，30.8k stars，238 commits，2026-08-04 页面数据），官方定位为"基于互联网搜索从零写出类 Wikipedia 长文并带引用"。方法论由两篇论文背书：STORM 论文（arXiv:2402.14207，NAACL 2024）与 Co-STORM 论文（arXiv:2408.15232，EMNLP 2024），方法名即论文名，属论文驱动流派。架构为两阶段管线（pre-writing 研究+大纲 → writing 生成带引用全文）+ 两种提问策略（Perspective-Guided Question Asking、Simulated Conversation）；引擎分 4 模块（知识策展/大纲生成/文章生成/文章润色），基于 dspy 模块化实现，5 个 LM 槽位可配不同模型以平衡成本与质量，10 种检索器抽象（YouRM/Bing/VectorRM/Serper/Brave/SearXNG/DDG/Tavily/Google/AzureAI）。Co-STORM 增加人机协作话语协议（LLM experts + Moderator + 人类用户三方，动态 mind map）。开放度高：MIT、pip install knowledge-storm、源码自托管、官方 live preview 免费试用（官方声称 70,000+ 人试用）、FreshWiki/WildSeek 数据集公开。官方诚实边界：系统无法产出 publication-ready 文章，编辑认为其"对 pre-writing 阶段有帮助"；论文另识别 source bias transfer 与 over-association 两类挑战。

## characteristics

- 论文驱动：方法名=论文名，NAACL 2024 + EMNLP 2024 双论文背书（C2、C22）
- 两阶段管线：pre-writing（研究+大纲）→ writing（生成带引用全文）（C3）
- 多视角提问：Perspective-Guided Question Asking + Simulated Conversation（C4、C5）
- 四模块引擎：knowledge curation / outline generation / article generation / article polishing，可定制（C6）
- 多 LM 编排：5 槽位模型分工，官方推荐分档控制成本（C8、C23）
- 多检索器抽象：10 种 RM + VectorRM 本地文档 grounding（C9、C10）
- 人机协作扩展：Co-STORM 三方话语协议 + 动态 mind map（C12、C13）
- 开放开源：MIT、pip 安装、源码自托管、live preview 免费试用、数据集公开可复现（C18、C19）
- 学术评估范式：FreshWiki 数据集 + Wikipedia 编辑反馈 + 与 baseline 量化对比（C15）
- 诚实边界：官方明示不产 publication-ready 文章（C16）；论文自识别 bias/over-association 挑战（C17）
- 框架血缘：基于 dspy 模块化实现（C14）
- 生态热度：30.8k stars 高关注（C20）

- 与 GPT Researcher 的关系：S001 采录中 GPT Researcher 官方自述受 STORM 论文启发；STORM 为论文驱动（C2/C22）、GPT Researcher 为工程驱动多 agent（LangGraph/AG2），是"论文驱动 vs 工程驱动"方法流派对比的核心证据对
- 与 Co-STORM 的关系：同仓库的人机协作扩展（C12/C13），与 STORM 单人自动流程构成"自动 vs 协作"分支
- 与 dspy 的关系：STORM 基于 dspy 实现（C14），可溯源至斯坦福 NLP 框架生态，与 OpenHands/LangGraph 等其他 agent 框架可对比

- 与 Wikipedia 编辑工作流的关系：官方明确定位为 pre-writing 辅助（C16），而非 publication-ready 生成器
- 与纯检索/无大纲方案的对立：STORM 主张"自动提出好问题是大纲生成核心"、直接提示 LM 提问效果不好（C4/C5 的动机陈述），隐含与简单 prompt 式 RAG 方案的对比

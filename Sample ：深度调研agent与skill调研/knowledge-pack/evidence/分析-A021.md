## summary

本文为两源合并分析。源A（Cognition 博客）主张：以"共享上下文、行动携带隐含决策"两条上下文工程原则为纲，默认排除多 agent 架构，推荐单线程线性 agent 并加上下文压缩模型应对长任务；论证以 Flappy Bird 示意例、Claude Code 与 Edit Apply Models 行业观察支撑，无对照实验，属于观点主张。源B（Co-STORM 论文）主张：复杂信息寻求应让用户观察并偶尔引导多 LM agent 对话（用户/专家/主持人三方协议），以动态 mind map 追踪话语并降低认知负荷；以 WildSeek 数据集、自动评估（优于 RAG Chatbot 与 STORM+QA）与 IRB 批准的人工评估（70%/78% 偏好）支撑，属于有实验数据的学术声称。两源在同一"多 agent 是否可靠"问题上立场对立：Cognition 认为 2025 年多 agent 协作只产生脆弱系统，Co-STORM 则构建了带人类参与的多 agent 系统并报告积极结果。

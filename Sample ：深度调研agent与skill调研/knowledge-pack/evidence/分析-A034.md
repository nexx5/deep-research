# 分析-A034：OpenAI《Operator System Card》单源分析

## summary

本文是 OpenAI 官方安全文档（System Card，2025-01-23 发布，2025-03-11 追加 API 段），披露 Operator（CUA 模型研究预览）发布前的安全工作全貌。核心内容五块：①**身份与训练**：Operator=CUA 研究预览；监督学习（感知/输入控制）+ 强化学习（推理/纠错/适应）；训练数据为公开 ML 数据 + web crawl + 人类训练师示范；②**风险识别**：综合先前部署反馈、第三方红队、内部测试与 Legal/Security/Policy 反馈；策略按任务/动作风险严重度分级，高风险动作需人工监督与确认，过高风险任务（如股票买卖）完全禁止；外部红队 20 国 24 语言，因互联网访问限制用 mock 环境、自认可能无法完整捕获最坏现实风险；③**前沿评估**：按 Preparedness Framework 评估四类前沿风险，Operator 继承 GPT-4o 的 persuasion（Medium）/cybersecurity（Low），净新增为视觉浏览；CBRN biorisk tooling 成功率 1%（OCR/字符计数失败为主因）、模型自主性主任务≤10%（视觉输入/光标输出模态为瓶颈），均判 Low 与 GPT-4o 一致；④**三类风险缓解**：harmful tasks（Usage Policies + 97% 拒绝率 + 系统层网站限制 + 部署后监控）、model mistakes（未缓解 100 提示 13 错误、confirmations recall 92%、proactive refusals recall 94%、watch mode）、prompt injections（31 场景 23% vs 无缓解 62%、monitor recall 99%/precision 90%/误报 46/13,704、一天内 recall 79%→99%）；⑤**API 披露与局限自述**：computer-use-preview 发布（Tiers 3-5），自评四类 API 风险（OSWorld 38.1%、系统消息修改增越狱、注入影响加重、规模滥用），给出三项措施；承认 CUA 早期局限与对抗鲁棒性为开放问题。

作为浏览器代理流派（执行侧）安全维度的一手官方证据，本文对生态观察的价值：完整呈现该流派"分层安全"设计范式（三类风险 × 四层部署）、可半独立核验的安全评测数字（带测试条件与样本数）、失败场景归因（OCR/文本编辑弱）与官方自述能力边界。官方声称 + 内部评测口径为主，评测数字给出样本数与条件、可部分复现，但与独立第三方评测在验证层面存在张力。

## characteristics

- 官方安全文档（System Card），OpenAI 立场，2025-01-23 + 2025-03-11 API 追加段
- 浏览器代理流派（执行侧）安全设计一手官方证据
- 分层安全范式：三类风险（harmful tasks / model mistakes / prompt injections）× 四层部署（模型训练/系统级/产品设计/持续策略）
- 三方不协调视角：user / model / website
- Preparedness Framework 前沿评估：CBRN 1%、自主性主任务≤10%，均 Low 与 GPT-4o 一致
- 评测数字带测试条件与样本数（97%/92%/94%/23%/99% recall/90% precision/13/100/46/13,704）
- 失败模式归因：OCR 与字符计数、视觉文本编辑（nano/VS Code）、随机串（DNA/API key/钱包地址）为 OCR 难点
- 模型错误基线实测（未缓解 100 提示 13 错误）
- 官方自认局限：红队 mock 环境可能不完整、评测 100% ≠ 实际部署、对抗鲁棒性开放
- API 安全披露（computer-use-preview）
- 官方声称 + 内部评测口径为主；数字可半独立复现但缺独立第三方复现

## opposing_to

- **官方自证 vs 独立第三方验证**：本文所有安全评测数字（97%/92%/94%/23%/99% recall 等）均为 OpenAI 内部口径——评测集、场景、基准由官方构建，无独立第三方复现；与"独立安全评测"视角存在验证层面张力。客观记录：数字带测试条件可部分复现，但"Safety 100% 评测不代表实际部署表现"亦为官方自认（断言 14 边界）。
- **过度拒绝 vs 可用性**：官方自认 Operator 过度拒绝显著多于 GPT-4o（not_overrefuse 55% vs GPT-4o 90%），即安全谨慎以可用性为代价——与"少拒绝、高可用"的 agent 设计取向形成张力（客观记录，不判优劣）。
- **系统卡分层口径 vs 技术博客分层口径**：本文称"四层部署"（模型训练/系统级/产品设计/持续策略），S032 技术博客称"三层部署"（模型本身/Operator 系统/部署后流程）——同一模型的缓解框架在两篇官方文档中统计粒度不同（客观记录，可能为表述视角差异）。
- **"与 GPT-4o 一致 Low 风险" vs 新增能力面**：本文判定 Operator 前沿风险无超出 GPT-4o 的增量（CBRN/自主性均 Low），但同时记录其净新增能力（视觉浏览）与实测失败（biorisk 1%、自主性主任务≤10%）——"能力新增"与"风险无增量"并存为官方评估结论（客观记录，不判其合理性）。
- **红队覆盖声明 vs 测试环境限制**：本文强调 20 国 24 语言的外部红队规模，同时自认"mock 环境发现可能无法完整捕获最坏现实风险"——覆盖广度与场景真实度之间的张力为官方自己承认。

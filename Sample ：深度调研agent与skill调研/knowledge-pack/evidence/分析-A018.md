## summary

本条单源分析针对合并采录 S018（dspy 框架 + STORM live preview）。核心发现：dspy 是斯坦福 NLP 的编程式提示优化框架（MIT、36.6k stars），而 STORM/Co-STORM 官方 README 明确声明其"高度模块化地基于 dspy 实现"，且 requirements.txt 首行即 dspy_ai==2.4.9——STORM 不是与 dspy 平行的独立方案，而是 dspy 生态之上的一层知识策展应用。live preview（storm.genie.stanford.edu）为官方免费在线服务，首屏称"研究原型/交互式知识策展"，获 Microsoft Azure 云信用资助，实测需先勾选服务条款；官方同时自我限定"不能产出可直接发表的文章"。这为生态观察提供了一手技术流派证据：论文驱动 + 编程式优化 + 开放开源 + 免费在线试用的组合形态。

## characteristics

- 编程式提示优化（技术流派：prompt as program）
- 斯坦福学术生态双组织（stanfordnlp 框架层 / stanford-oval 应用层）
- 论文驱动（ICLR/NAACL/EMNLP 多论文背书）
- 开放开源（MIT）与免费在线服务（Azure 云信用资助）并行
- 模块化 + 多LM分工（litellm 统一接入）
- 检索器生态丰富（10+ 类型，含 Tavily/SearXNG/Google 等）
- 使用门槛：服务条款勾选（低门槛但非零门槛）
- 官方自限定位（研究原型/预写辅助，非发表级）

## opposing_to

- 与"纯提示工程（手工 prompt）"流派对立：dspy 明确主张编程式替代 brittle prompts（该对立是框架自我定位，非独立判断）
- 与"黑盒/闭源付费深度调研服务"形态对立：dspy+STORM 走 MIT 开源 + 免费在线 + 学术透明路线；生态内与 OpenAI Deep Research 等付费服务形成形态对照（客观陈述形态差异，不评优劣）
- 与"强调产物可直接发表"的宣称对立：STORM 官方自我限定为预写辅助，与第三方声称"99% factual accuracy"（未经官方确认）存在口径差异（官方声称 vs 第三方转述分开记录）

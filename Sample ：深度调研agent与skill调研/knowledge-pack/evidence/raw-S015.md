## 功能对比表（官方声称）

| 维度 | 手动研究 | AI聊天机器人 | Manus 广泛研究 |
| --- | --- | --- | --- |
| 方法 | 以人为本，线性执行 | 单个AI协助 | 并行多代理协调 |
| 速度 | 每个分析周期的天数到周数 | 距离上下文饱和还有几个小时 | 分钟，无论规模大小 |
| 比例 | 受到认知和时间限制的约束 | 由于上下文窗口饱和而导致超过8-10个项目时性能下降 | 无缝扩展到数百个 |
| 质量 | 受人为变异和疲劳的影响 | 渐进性退化伴随更高的幻觉风险 | 在任何规模上保持统一的质量 |
| 输出 | 非结构化笔记和来源链接 | 压缩摘要导致细节丢失 | 完成报告和数据集 |

## 上下文过载问题（官方论述）

- 过多的背景信息会导致 AI 失效：让聊天机器人分析50家公司，前5家详细、到第20家变简短、第50家只剩泛泛之谈。
- 为什么会发生：传统 AI 拥有固定的"记忆"。随着处理的项目增多，先前的上下文内容会占据空间。空间越少=质量越低。

## 是什么让广泛研究与众不同（官方声称）

1. 真正的并行处理：每个子代理独立运行，具备完整功能：拥有自己的虚拟机、工具和互联网访问权限。
2. 每个项目都提供新的背景：传统 AI 积累上下文，广泛研究为每个项目提供一个干净的起点。
3. 集中的协调：主代理分配任务并收集结果。子代理之间从不相互沟通。这可以防止上下文污染并减少幻觉。

## 现实世界使用案例（官方展示）

## 工作原理（官方声称，4步）

1. 任务分解：主代理将您的请求分解为数百个独立的子任务
2. 并行执行：每个子任务都有一个专门的代理，并且有新的上下文
3. 自动化处理：子代理独立地研究、分析和创建
4. 汇聚一切：主代理收集所有结果并综合成最终报告

# 页面4：帮助中心·积分退款政策 https://help.manus.im/zh-CN/articles/12992237（2026-08-04 抓取）

## 官方政策声明

> 在 Manus，我们使用积分系统来让我们的 AI Agent 代表您执行各种任务。
> 如果我们的平台由于我们这边的技术问题而未能交付，我们认为您有权获得该任务所使用的积分的退款。

## 何时发放积分退款（官方定义）

错误 = Manus 平台中的技术错误或故障，它阻止 AI Agent 按预期完成任务或导致其行为方式出乎意料。

可退款情形：
- 平台错误：AI Agent 由于内部服务器错误、工具故障或意外系统崩溃而未能执行任务。
- 工具误用：AI Agent 以直接违反其文档说明的方式错误地使用工具，导致任务失败。
- 执行不完整：AI Agent 在任务中途停止，没有正当理由（例如，不是因为达到限制或收到用户停止命令），并且未能交付任何结果。

## 何时不发放积分退款（官方定义）

| 场景 | 描述 |
| --- | --- |
| 改变主意 | 在 AI Agent 已经开始或完成工作后，您决定不再需要完成该任务。积分会在 Agent 工作时消耗，且此工作无法撤销。 |
| 指令不明确 | 您的指令模糊、矛盾或不完整，导致 AI Agent 做出合理的解释，但该解释与您未说明的期望不符。 |
| 主观不满意 | AI Agent 已按要求完成任务，但您对结果的创造性或主观方面不满意。 |
| 外部因素 | 任务失败是由于 Manus 无法控制的第三方网站、API 或服务问题（例如，网站宕机、外部 API 返回错误）。 |
| 达到任务限制 | 任务因达到预设的安全或资源/知识库限制而停止，这是一个标准操作程序。 |

## AI 驱动的退款审核流程（官方声称）

1. 请求提交：用户提交退款请求并分享任务链接
2. AI 审核启动：审核 AI 被授予对指定任务完整执行历史的临时只读访问权限，包括所有步骤、工具输入/输出和系统日志
3. 彻底分析：AI Agent 审查整个任务历史记录，识别异常、错误或偏差，与内部工具文档和平台健康日志交叉引用
4. 决定：确认错误则积分退款自动处理到账户

# 分析-A003：STORM（stanford-oval/storm）单源分析

## summary

STORM 是"论文驱动"深度调研方法流派的代表性开源证据：方法名即论文名，两篇会议论文（NAACL 2024 / EMNLP 2024）背书，来自斯坦福 OVAL 实验室。其核心知识贡献集中在 pre-writing 阶段——把"自动研究并准备大纲"建模为视角发现 + 模拟对话 + 信息策展三步（C4/C5），主张"提出好问题"是大纲自动化核心（C3）。工程面为两阶段 Runner 管线（C3/C7）、四模块可定制引擎（C6）、5 槽位多 LM 编排（C8）与 10 种检索器抽象（C9），实现基于 dspy（C14）。Co-STORM 在同一仓库内提供人机协作分支（三方话语协议 + mind map，C12/C13）。开放度在同类中较高：MIT、pip、源码自托管、官方免费 live preview、双数据集公开（C18/C19）。官方对边界诚实：明示不产 publication-ready 文章、定位 pre-writing 辅助（C16），论文自识别来源偏见迁移与无关事实过度关联两类挑战（C17）。成本维度仅有"模型分档平衡"的实践建议，无公开单次成本数字（C23）。社区层面有 30.8k stars 的高关注（C20），issues 呈现多语言检索、失败模式文档等开放需求（C24）。

## characteristics

- 论文驱动方法论：方法名即论文名、双会议论文背书、学术机构出品（K2、C22）
- 两阶段 + pre-writing 创新重心：视角发现/模拟对话/大纲生成（K3）
- 多视角提问机制：perspective-guided question asking + simulated conversation（C4/C5）
- 四模块可定制引擎 + Runner 阶段开关（C6/C7）
- 多 LM 编排与成本平衡策略：5 槽位分档（C8/C23）
- 多检索器抽象：10 种 RM + VectorRM 本地文档（C9/C10）
- 人机协作扩展：Co-STORM 三方话语协议 + mind map（K8）
- 高开放度：MIT/pip/源码/免费 preview/数据集公开（K6）
- 学术评估范式：FreshWiki 数据集 + 编辑反馈 + baseline 量化对比（K4）
- 边界诚实：官方明示非 publication-ready（K5）
- 基于 dspy：与斯坦福 NLP 框架生态有血缘（C14）

## opposing_to（可能对立的方向，客观陈述）

- 与"工程驱动"深度调研方案（如 GPT Researcher 类多 agent 编排、LangGraph 流水线）对立：STORM 以论文/学术评估范式立身，工程方案以工程集成/成本量化/可观测性立身；两者方法流派不同（论文驱动 vs 工程驱动），非优劣判断
- 与"轻量单 agent 检索生成"方案对立：STORM 主张直接提示 LM 提问效果不好、必须显式建模视角与模拟对话（C4/C5 动机陈述），与简化 prompt 式 RAG 路线在方法论上相左
- 与"纯自动"路线的对立来自其自身扩展：Co-STORM 引入人类参与（观察/注入话语）作为更受控的信息寻求方式，隐含对"全自动生成即可用"假设的修正（C12/C16）
- 与"产出即成稿"预期的对立：官方明示文章需要大量编辑、定位为 pre-writing 辅助（C16），与把深调研系统当作成品报告生成器的使用预期对立
- 与"多语言/多源语言覆盖"的对立：当前检索以英文为主（社区 #378 提出缺口，C24），对非英文调研需求的覆盖可能不足（社区输入，非官方确认）

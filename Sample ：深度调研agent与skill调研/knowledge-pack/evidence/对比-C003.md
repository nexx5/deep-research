# 跨源对比-C003：深度调研方法流派三角与评测基准体系（客观观察）

## 一、方法流派三角（单 agent / 多 agent / 人机协作）

### 1. 单 agent 递归深化流派（代表：dzhng/deep-research，S009）

- **架构**：单一 agent 递归循环，极简实现（<500 LoC 目标），无编排器/无子代理（源码级证据，S009）
- **依赖**：Firecrawl 搜索抓取（单一第三方服务），无记忆库/无持久化（源码级证据）
- **工作流**：depth/breadth 参数化迭代检索 → 递归深化 → Markdown 报告 + Sources 引用
- **方法主张**：单 agent 连续深化足够；简单、可控、成本低
- **证据层级**：架构为源码可复核（M）；定位/极简目标为官方声称（L）

### 2. 多 agent 编排流派（代表：OpenDeepResearch，S002；GPT Researcher 多 agent 变体，S001）

- **架构**：LangGraph 图编排 + supervisor 拆解子主题 → 并行子 agent（隔离上下文）→ 压缩 findings → one-shot 报告（源码级证据，S002）
- **方法主张**：研究阶段多 agent 并行有效；写作阶段必须单 agent（官方第一手教训：并行写报告导致章节不连贯，S002）
- **证据层级**：架构为官方博客+源码双源一致（H）；性能/成本为官方自报（M）

### 3. 反多 agent 主张（Cognition《Don't Build Multi-Agents》，S021）

- **核心论证**：多 agent 系统引入复杂度、失败率、成本与脆弱性；主张上下文工程 + 单线程线性 agent（上下文压缩模型）足以处理复杂任务
- **案例**：Claude Code（自家产品）采用单 agent 方案
- **证据层级**：观点主张博客，**无实验支撑**（弱/中论证，S021 已标注）
- **与 OpenDeepResearch 的关系**：A002 conflict_flags 已记录——边界差异为"研究阶段 vs 全流程"，OpenDeepResearch 在写作阶段与 Cognition 立场一致

### 4. 人机协作流派（Co-STORM，S021 + S003）

- **架构**：三方话语协议（human / AI agent / AI assistant）+ 动态 mind map（S021 论文级证据）
- **方法主张**：human-in-the-loop 多 agent 系统——用户参与话语以缓解决策分散与认知负荷（论文声称，有实验评估：自动+人工，单源自报）
- **与纯自动派生的关系**：Co-STORM 为 STORM（S003）的交互化扩展，隐含对"全自动生成即可用"假设的修正
- **流派归属**：多 agent 但以用户参与缓解——介于纯多 agent 与纯单 agent 之间

### 5. 论文驱动流派的技术底座（STORM + dspy，S003 + S018）

- **技术关系闭环**：STORM 官方 README 明示"Both STORM and Co-STORM are implemented in a highly modular way using dspy"；requirements.txt 首行 dspy_ai==2.4.9；dspy 论文清单收录 STORM 论文——三方互证（S018）
- **流派特征**：方法名=论文名、学术评估范式（FreshWiki/编辑反馈）、多 LM 分槽编排（5 槽位）、10 检索器抽象（S003）
- **成本**：dspy 官方声称优化成本 ~$2/20min（第三方未确认，S018 已标注）

### 流派对照小结（客观陈述）

| 维度 | 单 agent（dzhng） | 多 agent（OpenDeepResearch） | 反多 agent（Cognition） | 人机协作（Co-STORM） |
|---|---|---|---|---|
| 实现复杂度 | 极简 | 高（编排器+子代理+压缩） | 主张单线程 | 高（三方协议+mind map） |
| 并行度 | 无 | 高（研究阶段） | 无 | 中（用户参与） |
| 用户参与 | 无 | 澄清机制（可选） | 无 | 核心（human-in-the-loop） |
| 证据强度 | 源码级（M） | 官方博客+源码（H） | 无实验（L/M） | 论文实验（M，单源自报） |
| 知识复用 | 无记忆库 | 无长期记忆（open question） | 未涉及 | 未涉及 |

## 共识

1. **方法流派多样但非对立排他**：单 agent/多 agent/人机协作各有适用证据，流派归类是客观观察（项目 core_questions 4），不判优劣
2. **评测基准是"官方声称 vs 独立验证"的仲裁基座**：DRB（USTC）已成为生态事实标准（OpenDeepResearch/hyperresearch/Gemini 均引用），但必须区分量纲
3. **官方附属基准 ≠ 独立验证**：hyperresearchbench 案例表明，官方自报"领先"须以第三方独立核验为准（S019 明确标注）
4. **引用可靠性是跨流派共同关注**：付费侧（S024 论文量化 3-13% 引用幻觉率）vs 开源侧（S002 强制编号引用、S004 引用-句子绑定）形成对照

## 分歧（客观列出）

1. **多 agent 有效性**：OpenDeepResearch（S002，研究阶段多 agent 有效）vs Cognition（S021，全流程反多 agent）——边界差异已记录，非直接矛盾
2. **人机协作定位**：Co-STORM 主张 human-in-the-loop 降低认知负荷（S021 论文声称）vs 纯自动派（STORM 基础版，S003 隐含全自动立场）——不同产品定位
3. **评测指标维度**：RACE/FACT（报告质量+引用，USTC）vs 答案+trace（FS-DRB）vs 检查点准确率（AIMultiple，S013）——三类评测范式代表不同"什么算深度调研能力"的定义（客观差异，非优劣）

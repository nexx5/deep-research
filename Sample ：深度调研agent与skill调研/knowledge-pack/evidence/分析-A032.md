# 分析-A032：OpenAI《Computer-Using Agent》单源分析

## summary

本文是 OpenAI 官方技术博客（2025-01-23），宣告 Computer-Using Agent（CUA）——Operator 的技术底座模型。文章核心内容四块：①**架构**：CUA=GPT-4o 视觉 + 强化学习推理，通过"原始像素感知 + 虚拟鼠标/键盘"的通用界面（screen/mouse/keyboard）与 GUI 交互，不依赖 OS/Web 专用 API，运行于感知-推理-行动迭代循环；②**评测**：声称 OSWorld 38.1%（人类 72.4%）、WebArena 58.1%（人类 78.2%）、WebVoyager 87%（任务较简单）的新 SOTA，并观察 test-time scaling；③**Operator 试用**：给出多场景成功/尝试次数表，展示简单重复 UI 任务可靠（10/10）、提示细节敏感（tagvenue 8/10 vs 3/10）、不熟悉 UI 与文本编辑弱（html5editor 4/10）、复杂条件任务低（Redfin 3/10）；④**安全**：misuse/model mistakes/frontier risks 三类风险 + 模型-系统-部署后三层缓解，含提示注入防御（红队仅漏 1 例）与前沿风险无增量评估。

作为浏览器代理流派（computer use）技术底座的一手官方证据，本文对生态观察的价值：给出该流派"通用界面 vs 专用 API"的接口哲学、SOTA 评测数字与测试条件、官方自述局限与安全设计全貌。官方声称为主，评测数字附 previous SOTA 来源链接（Anthropic/ServiceNow/Kura）可半独立核验。

## characteristics

- 官方技术博客（OpenAI 立场），Research/Release 栏目
- 浏览器代理流派 / computer use 技术底座（Operator 的模型底座）
- 通用界面哲学：screen/mouse/keyboard，无 OS/Web 专用 API
- 评测数字 + previous SOTA 来源链接（Anthropic/ServiceNow/Kura）可半独立核验
- test-time scaling 观察
- Operator 试用实测表（成功/尝试次数）——官方自曝已知强弱项
- 分层安全设计（三类风险 × 三层部署）
- 提示注入防御（Cautious navigation/Monitoring/Detection pipeline）
- 发布范围：美国 Pro 用户研究预览
- 局限自述：不熟悉 UI、文本编辑弱、提示敏感、复杂任务低成功

## opposing_to

- 与"专用 API/工具接口"型 agent 方案（潜在对立）：CUA 主张无需 OS/Web 专用 API、以像素+虚拟鼠标键盘为通用接口（断言 3/4）；与依赖浏览器 API、DOM 结构化操作或专用工具定义的 agent 方案在接口设计取向上对立——这是"通用界面 vs 专用接口"两种执行侧哲学的对照点。
- 与"文本/检索型"agent（调研侧，本项目主调研对象）：CUA 是执行侧（在浏览器/OS 中操作完成任务），与检索-阅读-分析型 agent 目标不同；"调研 vs 执行"边界的两侧各自独立演进，CUA 代表执行侧技术底座。
- 官方"new state-of-the-art"声称 vs 评测表 previous SOTA：WebVoyager 行 previous SOTA 87.0%（Kura）与 CUA 87.0% 并列，与导语"sets new state-of-the-art"存在潜在张力（客观并列记录，不判谁对；表格列对应存在转换错位风险，需以官方 eval PDF 核对）。
- 安全声称的自证性：提示注入防御"红队仅漏 1 例"（断言 21）与前沿风险"无增量风险"（断言 22）均为官方内部口径，与"外部独立安全评测"视角存在验证层面张力（客观记录）。

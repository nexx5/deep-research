## 摘要

两源合并采录：①Cognition 官方博客《Don't Build Multi-Agents》（作者 Walden Yan，2025-06-12）提出"上下文工程"两原则，明确反对多 agent 架构（批评 OpenAI Swarm、Microsoft AutoGen），主张单线程线性 agent 加上下文压缩模型；②Co-STORM 论文（arXiv:2408.15232，EMNLP 2024 Main）提出人机协作深度调研范式——用户观察并偶尔引导多个 LM agent 对话（用户/多视角专家/主持人三方话语协议），用动态 mind map 追踪话语、降低认知负荷，自动+人工评估声称优于搜索引擎与 RAG 聊天机器人。两源构成"反多 agent"与"多 agent 人机协作"的方法流派对立证据。

## evidence

### 源A（Cognition 博客）

#### 证据1（claim 1：反对多agent）
- source: S021
- location: 博客引言引用块
- quote: "In some cases, libraries such as https://github.com/openai/swarm by OpenAI and https://github.com/microsoft/autogen by Microsoft actively push concepts which I believe to be the wrong way of building agents. Namely, using multi-agent architectures"
- context: 作者点名批评两大主流多agent库，声明多agent架构是错误构建方式

#### 证据2（claim 2：分解架构脆弱）
- source: S021
- location: "A Theory of Building Long-running Agents" 段
- quote: "This is a tempting architecture... However, it is very fragile. The key failure point is this: Suppose your Task is 'build a Flappy Bird clone'..."
- context: 作者用 Flappy Bird 假想例子演示子agent误解子任务导致合并错位；作者自认例子"may seem contrived"

#### 证据3（claim 3/4：两原则）
- source: S021
- location: "Applying the Principles" 前两节
- quote: "Principle 1: Share context, and share full agent traces, not just individual messages"；"Principle 2: Actions carry implicit decisions, and conflicting decisions carry bad results"
- context: 作者声称两条原则"so critical, and so rarely worth violating"应默认排除不遵守的架构

#### 证据4（claim 7：Claude Code 案例）
- source: S021
- location: "Applying the Principles" 段
- quote: "As of June 2025, Claude Code is an example of an agent that spawns subtasks. However, it never does work in parallel with the subtask agent, and the subtask agent is usually only tasked with answering a question, not writing any code"
- context: 作者以 Claude Code 作为遵循原则的行业案例；subagent 好处是调查工作不留在主agent历史中

#### 证据5（claim 8：多agent现状判断）
- source: S021
- location: "Multi-Agents" 段
- quote: "it is evident that in 2025, running multiple agents in collaboration only results in fragile systems. The decision-making ends up being too dispersed and context isn't able to be shared thoroughly enough"
- context: 作者对多agent对话协作现状的判断，并引用 CAMEL（arXiv 2304.03442）与 MetaGPT 作为探索先例

### 源B（Co-STORM 论文）

#### 证据6（claim 10：人机协作范式）
- source: S021
- location: 摘要 / §3.1
- quote: "Unlike QA systems that require users to ask all the questions, Co-STORM lets users observe and occasionally steer the discourse among several LM agents. The agents ask questions on the user's behalf"
- context: 论文核心设计主张——以"学生旁听并参与老师/家长对话"的教育场景为隐喻

#### 证据7（claim 11：三方话语协议）
- source: S021
- location: §3.1 Collaborative Discourse Protocol
- quote: "the collaborative discourse, D = {u1, u2, ..., un}, consists of turn-based textual utterances ui from one of three roles: the user (§3.3), experts with diverse perspectives (§3.4), and a moderator guiding the discourse and injecting questions (§3.5)"
- context: 三方角色定义；采用混合主动性（mixed-initiative），用户可随时接管话语

#### 证据8（claim 12：动态mind map）
- source: S021
- location: §3.2 Tracking the Discourse with a Mind Map
- quote: "To help users track the discourse and reduce their cognition load, Co-STORM uses a tree-structured mind map M to dynamically organize collected information"
- context: mind map 通过 insert/reorganize 两操作更新；人工评估中80个快照71%准确追踪话语

#### 证据9（claim 13：与自动派生STORM对比）
- source: S021
- location: §1 Introduction
- quote: "producing the static report as the final outcome, STORM does not support any user interaction which is crucial in complex information seeking where there is no single, gold query, but queries evolve dynamically towards a goal"
- context: 论文指出 STORM 自动派生调研的局限，以此为 Co-STORM 引入交互的动机

#### 证据10（claim 15：自动评估结果）
- source: S021
- location: §5.3 Table 3
- quote: "Co-STORM outperforms it [STORM+QA], particularly in the Depth and Novelty aspects... For discourse quality, the question-answering turns in Co-STORM significantly outperform both baselines in terms of Consistency and Engagement"
- context: 报告质量 Depth 3.77 vs STORM+QA 3.43、Novelty 3.05 vs 2.50（† p<0.05）；评估方法：Prometheus 2 评估器 + 模拟用户 + 配对t检验

#### 证据11（claim 16：主持人消融）
- source: S021
- location: §5.4 Ablation Studies
- quote: "removing the moderator has a greater negative impact than reducing the number of experts"
- context: w/o Multi-Expert（1专家+1主持人）与 w/o Moderator（N专家+0主持人）均差于完整系统

#### 证据12（claim 17：人工评估）
- source: S021
- location: §6.2 Table 4
- quote: "70% preferred Co-STORM over the search engine, and 78% preferred it over the RAG chatbot for the overall information-seeking experience"
- context: Serendipity vs Search Engine p=0.030、vs RAG p=0.009（显著）；评估方法：IRB批准、20志愿者、5点Likert、配对比较

#### 证据13（claim 18：认知负荷声称）
- source: S021
- location: §6.2 参与者反馈 + §8 Conclusion + Limitations
- quote: "Participants find that Co-STORM facilitates serendipitous discovery and requires less mental effort"；参与者评论"Co-STORM is so much less mentally taxing for me to use"；局限"compared to the RAG Chatbot, Co-STORM has higher latency"
- context: 论文声称降低心智努力；同时自述延迟更高、未定制先验知识等局限

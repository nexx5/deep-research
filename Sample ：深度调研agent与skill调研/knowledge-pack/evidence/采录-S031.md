# 采录-S031：DSPy 论文 + Anthropic《Building Effective Agents》

## 摘要

本采录合并两源：①DSPy 论文（arXiv:2310.03714，Stanford，2023-10-05）——提出将 LM pipelines 抽象为文本转换图、以可参数化模块+编译器自改进的编程模型，是论文驱动流派（如 STORM）实现的技术底座；②Anthropic《Building Effective Agents》（2024-12-19）——官方工程指南，给出 agentic systems 的工作流 vs agent 分类（5 种 workflow 模式 + agents）、构建原则与框架批判，与 Cognition 单 agent 主张（S021）构成同源对照。论文为学术声称（摘要级证据），博客为官方主张（经验观察），论证强度分别标注。

## key_claims

### 源A：DSPy 论文（学术声称，证据=arXiv 摘要原文，非全文细读）

- **CL-S031-001【定义】** DSPy 是一种编程模型，将 LM pipelines 抽象为文本转换图（text transformation graphs），即命令式计算图，LM 通过声明式模块调用。
  - boundary: 定义性声称，限于 DSPy 框架自身设计；"文本转换图"为论文术语
  - evidence: 摘要原文 "a programming model that abstracts LM pipelines as text transformation graphs, i.e. imperative computational graphs where LMs are invoked through declarative modules"
  - characteristics: 论文驱动/框架核心定义/编程模型/声明式模块

- **CL-S031-002【设计】** DSPy 模块可参数化，通过学习（创建和收集 demonstrations）应用 prompting、finetuning、augmentation、reasoning 技术的组合。
  - boundary: 限于论文提出的模块设计；"可学习"指通过 demonstrations 引导而非权重更新
  - evidence: 摘要原文 "DSPy modules are parameterized, meaning they can learn (by creating and collecting demonstrations) how to apply compositions of prompting, finetuning, augmentation, and reasoning techniques"
  - characteristics: 自改进/参数化模块/演示收集/技术组合

- **CL-S031-003【设计】** DSPy 编译器优化任何 DSPy pipeline 以最大化给定指标（metric）。
  - boundary: 编译器行为声称，依赖给定 metric；摘要未详述优化算法
  - evidence: 摘要原文 "We design a compiler that will optimize any DSPy pipeline to maximize a given metric"
  - characteristics: 编译器/指标驱动/自改进

- **CL-S031-004【现状观察】** 论文主张：现有 LM pipelines 通常用硬编码 prompt templates（试错发现的冗长字符串）实现，缺乏系统化开发方法。
  - boundary: 论文对 2023 年现状的判断，属观察性声称非普适定律
  - evidence: 摘要原文 "existing LM pipelines are typically implemented using hard-coded 'prompt templates', i.e. lengthy strings discovered via trial and error"
  - characteristics: 问题陈述/prompt template 批判/现状观察

- **CL-S031-005【案例研究】** 两个案例研究显示：简洁 DSPy 程序可表达并优化复杂 LM pipelines——数学词问题推理、多跳检索、复杂问答、控制 agent loops。
  - boundary: 限于论文所述四类任务；"agent loops"仅提及未展开
  - evidence: 摘要原文 "succinct DSPy programs can express and optimize sophisticated LM pipelines that reason about math word problems, tackle multi-hop retrieval, answer complex questions, and control agent loops"
  - characteristics: 案例研究/任务覆盖/agent loops

- **CL-S031-006【定量声称】** 性能声称：编译几分钟内，几行 DSPy 使 GPT-3.5 与 llama2-13b-chat 自举 pipelines 超越标准 few-shot prompting（分别一般超过 25% 与 65%），并超越专家创建的 demonstrations 的 pipelines（最高 5-46% 与 16-40%）。
  - boundary: 论文实验声称（2023 年模型）；幅度随任务变化；摘要未详述评测集与统计口径
  - evidence: 摘要原文 "Within minutes of compiling, a few lines of DSPy allow GPT-3.5 and llama2-13b-chat to self-bootstrap pipelines that outperform standard few-shot prompting (generally by over 25% and 65%, respectively) and pipelines with expert-created demonstrations (by up to 5-46% and 16-40%, respectively)"
  - characteristics: 定量声称/自举/性能对比

- **CL-S031-007【定量声称】** 性能声称：编译到开放小模型（770M 参数 T5、llama2-13b-chat）的 DSPy 程序，与依赖专家编写 prompt chains 的专有 GPT-3.5 方案有竞争力。
  - boundary: 实验声称；"有竞争力"为作者判断；小模型清单限于论文所述
  - evidence: 摘要原文 "DSPy programs compiled to open and relatively small LMs like 770M-parameter T5 and llama2-13b-chat are competitive with approaches that rely on expert-written prompt chains for proprietary GPT-3.5"
  - characteristics: 开放模型/小模型/专有模型对比

- **CL-S031-008【开源事实】** DSPy 开源可用（github.com/stanfordnlp/dspy）。
  - boundary: 论文所述开源地址；访问日仓库存活性未二次验证
  - evidence: 摘要原文 "DSPy is available at this https URL (github.com/stanfordnlp/dspy)"
  - characteristics: 开源/仓库/生态可获取性

### 源B：Anthropic《Building Effective Agents》（官方主张，证据=博客原文；立场性内容标注）

- **CL-S031-009【经验观察·立场】**
  Anthropic 观察：与数十个行业团队合作，最成功的 agent 实现使用简单、可组合的模式，而非复杂框架或专门库。
  - boundary: 基于 Anthropic 客户合作与自建经验（官方立场）；"最成功"未给出度量标准与公开数据
  - evidence: 博客原文 "Consistently, the most successful implementations weren't using complex frameworks or specialized libraries. Instead, they were building with simple, composable patterns."
  - characteristics: 官方主张/经验观察/简单可组合/反复杂框架

- **CL-S031-010【分类定义】** Anthropic 将各变体统称 agentic systems，并区分：workflows（LLM 与工具经预定义代码路径编排）vs agents（LLM 动态指导自身过程与工具使用，保持对任务完成方式的控制）。
  - boundary: Anthropic 提出的定义性区分；文中承认 "Agent" 一词行业定义不一
  - evidence: 博客原文 "Workflows are systems where LLMs and tools are orchestrated through predefined code paths. Agents, on the other hand, are systems where LLMs dynamically direct their own processes and tool usage, maintaining control over how they accomplish tasks."
  - characteristics: 分类框架/workflows vs agents/术语定义

- **CL-S031-011【工程建议·立场】** 建议：找到最简单解决方案，仅在需要时增加复杂度；agentic systems 常以延迟与成本换取更好任务性能，应权衡此取舍（有时不应构建 agentic 系统）。
  - boundary: 官方工程建议，非可验证事实
  - evidence: 博客原文 "we recommend finding the simplest solution possible, and only increasing complexity when needed. This might mean not building agentic systems at all. Agentic systems often trade latency and cost for better task performance"
  - characteristics: 工程建议/复杂度克制/成本-延迟权衡

- **CL-S031-012【适用性主张·立场】** workflows 为明确定义的任务提供可预测性与一致性；agents 更适合需要灵活性与模型驱动决策的大规模任务；对许多应用，优化单次 LLM 调用+检索+上下文示例通常已足够。
  - boundary: 官方建议性主张
  - evidence: 博客原文 "workflows offer predictability and consistency for well-defined tasks, whereas agents are the better option when flexibility and model-driven decision-making are needed at scale. For many applications, however, optimizing single LLM calls with retrieval and in-context examples is usually enough."
  - characteristics: 适用性指引/分层建议

- **CL-S031-013【框架批判·立场】** 框架建议：开发者应先直接使用 LLM API（许多模式几行代码即可实现）；框架常增加抽象层掩盖底层 prompts/responses 使调试困难，且易诱使增加不必要复杂度；若用框架须理解底层代码（对框架底层行为的错误假设是客户错误的常见来源）。
  - boundary: 官方立场（Anthropic 自身提供 API 服务，存在立场背景）
  - evidence: 博客原文 "We suggest that developers start by using LLM APIs directly... they often create extra layers of abstraction that can obscure the underlying prompts and responses, making them harder to debug... Incorrect assumptions about what's under the hood are a common source of customer error."
  - characteristics: 框架批判/API 优先/抽象层风险

- **CL-S031-014【构建块】** 基础构建块为增强 LLM（augmentations：retrieval、tools、memory）；当前模型可主动使用这些能力——生成搜索查询、选择工具、决定保留信息；实现关注两点：针对用例定制 + 为 LLM 提供易用且文档良好的接口（可经 Model Context Protocol 集成第三方工具生态）。
  - boundary: 官方设计主张；"当前模型可主动使用"指 Anthropic 自家模型能力
  - evidence: 博客原文 "The basic building block of agentic systems is an LLM enhanced with augmentations such as retrieval, tools, and memory. Our current models can actively use these capabilities—generating their own search queries, selecting appropriate tools, and determining what information to retain."
  - characteristics: 增强 LLM/检索-工具-记忆/MCP

- **CL-S031-015【模式分类】** 五种 workflow 模式：prompt chaining（提示链）、routing（路由）、parallelization（并行化，含 sectioning 分块与 voting 投票两变体）、orchestrator-workers（编排器-工人）、evaluator-optimizer（评估器-优化器）。
  - boundary: Anthropic 归纳的生产模式分类，非穷尽性列表
  - evidence: 博客正文各 workflow 章节标题与定义
  - characteristics: 工作流分类/五种模式/工程模式库

- **CL-S031-016【模式定义】**
  orchestrator-workers：central LLM 动态分解任务、委派给 worker LLM 并综合其结果；与并行化的关键区别是灵活性——子任务不预定义，由编排器根据具体输入决定。
  - boundary: 模式定义（官方主张）；未提 worker 数量上限或委派层级
  - evidence: 博客原文 "a central LLM dynamically breaks down tasks, delegates them to worker LLMs, and synthesizes their results... the key difference from parallelization is its flexibility—subtasks aren't pre-defined, but determined by the orchestrator based on the specific input."
  - characteristics: 多 worker 协作/动态委派/模式定义

- **CL-S031-017【运行机制】**
  agents 运行方式：从人类命令或互动讨论开始；任务明确后独立计划与操作，可返回人类获取信息/判断；执行中每步从环境获取 ground truth（工具调用结果、代码执行）评估进展；可在检查点或遇到障碍时暂停等待人类反馈；常含停止条件（如最大迭代数）。
  - boundary: 官方对 agent 运行机制的描述性主张
  - evidence: 博客原文 "Agents begin their work with either a command from, or interactive discussion with, the human user... it's crucial for the agents to gain 'ground truth' from the environment at each step (such as tool call results or code execution)... Agents can then pause for human feedback at checkpoints or when encountering blockers... it's also common to include stopping conditions (such as a maximum number of iterations)"
  - characteristics: agent 运行机制/ground truth/人工检查点/停止条件

- **CL-S031-018【适用条件·立场】** 何时用 agents：开放性问题、难以或不可能预测所需步数、不能硬编码固定路径；需对模型决策有一定信任度；自治带来更高成本与复合错误（compounding errors）风险，建议沙盒环境广泛测试 + 适当 guardrails。
  - boundary: 官方建议；风险陈述为定性判断
  - evidence: 博客原文 "Agents can be used for open-ended problems where it's difficult or impossible to predict the required number of steps, and where you can't hardcode a fixed path... The autonomous nature of agents means higher costs, and the potential for compounding errors. We recommend extensive testing in sandboxed environments, along with the appropriate guardrails."
  - characteristics: 适用条件/成本-复合错误风险/guardrails

- **CL-S031-019【三原则·立场】** 实现 agent 的三条核心原则：保持设计简单（simplicity）；通过明确展示规划步骤实现透明（transparency）；通过彻底的工具文档与测试精心设计 agent-computer interface / ACI。
  - boundary: 官方原则性建议
  - evidence: 博客原文 "1. Maintain simplicity in your agent's design. 2. Prioritize transparency by explicitly showing the agent's planning steps. 3. Carefully craft your agent-computer interface (ACI) through thorough tool documentation and testing."
  - characteristics: 三原则/简单性/透明/ACI

- **CL-S031-020【工具工程·经验立场】**
  工具提示工程主张（附录2）：工具格式应给模型足够 token "思考"、贴近互联网自然文本、避免格式开销（行数计数、字符串转义等）；工具定义应得到与整体 prompt 同等的提示工程关注；SWE-bench 实现中团队在优化工具上花的时间比整体 prompt 更多（例：将工具改为强制绝对文件路径后模型用法无差错）。
  - boundary: 官方经验主张，基于 SWE-bench 开发经验；单案例证据
  - evidence: 博客附录2 原文 "Give the model enough tokens to 'think'... Keep the format close to what the model has seen naturally occurring in text on the internet... we actually spent more time optimizing our tools than the overall prompt... we changed the tool to always require absolute filepaths—and we found that the model used this method flawlessly."
  - characteristics: 工具工程/ACI/经验主张

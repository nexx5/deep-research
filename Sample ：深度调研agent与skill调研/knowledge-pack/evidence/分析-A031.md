# 分析-A031：DSPy 论文 + Anthropic《Building Effective Agents》单源分析

## summary

本分析覆盖两源合并采录（采录-S031，20 条断言），分两组看待：

1. **源A（DSPy 论文）**——论文驱动流派（STORM 技术底座）的学术证据。论文的核心立场是"用编程模型+编译器取代手工 prompt 工程"：把 LM pipelines 定义为文本转换图，模块可参数化学习 demonstrations 组合，编译器按指标优化。其价值在生态观察中定位为"系统性方法 vs 手工模板"这一方法流派的学术源头之一。
2. **源B（Anthropic 博客）**——agent 工程方法流派的官方主张。核心主张是"简单可组合优先、复杂度按需增加"，给出 workflows vs agents 的架构区分（5 种 workflow + agents 运行机制），并对复杂框架持批判态度。作为官方博客，其观察与建议带有 Anthropic 自身立场（API 优先、自家模型能力表述），但分类框架本身被行业广泛引用。

两源在"如何构建 LM 系统"问题上给出不同层面的回答：DSPy 主张以编译器抽象系统化优化（引入抽象），Anthropic 主张减少抽象、直连 API 从简起步（警惕抽象）。二者不直接对立，但取向张力可作为方法流派对照观察点。

## characteristics

- 论文驱动/学术声称（源A）：编程模型、声明式模块、编译器、自改进、demonstrations
- 官方主张/工程指南（源B）：workflows vs agents 分类、5 种模式、简单可组合、API 优先、ACI
- 两源共性：都关注"agent 循环"（论文的 control agent loops / 博客的环境反馈循环）
- 立场性：Anthropic 博客为官方立场（API 优先、自家模型能力、MCP），需区别于学术声称
- 生态定位：DSPy=论文驱动流派技术底座；Anthropic=agent 工程方法流派官方主张

## opposing_to

- 与 Cognition《Don't Build Multi-Agents》（S021）：Anthropic 将 orchestrator-workers（中央 LLM+多 worker）列为合法 workflow 并主张按需增加复杂度；Cognition 主张默认排除多 agent、单线程线性 agent。两方对多 agent 架构的态度存在张力（客观并列，本分析不判谁对）。
- 与"复杂框架"立场（潜在对立面）：DSPy 主张以编程模型+编译器引入抽象（CL-S031-001/003）vs Anthropic 主张减少抽象层、直连 API（CL-S031-013）——"系统化抽象 vs 从简直连"取向差异。
- 与"手工 prompt 工程"立场（潜在对立面）：DSPy 明确批判硬编码 prompt templates（CL-S031-004）。

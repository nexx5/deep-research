## summary

本文档对 nickscamara/open-deep-research（S011）做单源分析。该开源项目是 OpenAI Deep Research 实验的开源复刻路线之一（官方自称），核心技术主张是：用 Firecrawl 的商业 search+extract 抓取管道 + 推理模型替代 OpenAI 微调版 o3，实现 web 深度调研。架构上它是一套基于 Vercel ai-chatbot 模板的 Next.js 全栈聊天应用，核心为 route.ts 中的双模型 agent loop：router 模型（gpt-4o）以 streamText maxSteps=10 编排 search/extract/scrape（均走 Firecrawl）与 deepResearch 四工具；deepResearch 内置迭代循环（maxDepth=7、4.5 分钟硬时限），由 reasoning 模型（默认 o1-mini）反复"搜索→抽取→JSON 分析规划→迭代"直至综合出长文。检索通道完全依赖 Firecrawl 单一商业 API，无自建抓取管道；数据层依赖 Vercel Postgres/Blob + Upstash Redis；需 OpenAI/OpenRouter、Firecrawl、数据库、Redis 等多付费 key，无官方单次成本数据。开放程度为源码公开 + Apache-2.0（模板继承）+ 可自托管，但检索能力被商业 API 锁定；项目自 2025-05-07 后无提交，访问时点已停止维护约 15 个月。核心观察价值在于其为"商业抓取 API 流派"的代表性实现，与 Tavily 流派及自建管道流派构成检索通道策略对比证据。

## characteristics

- 检索通道策略：商业抓取 API 单一供应商（Firecrawl），无自建管道（C2）
- 双模型编排：router + reasoning 分工（C3）
- 迭代自规划 loop：gaps 驱动下一轮搜索（C4）
- 硬时限与深度上限：4.5 分钟 / maxDepth 7 / Hobby 60s（C5、C11）
- JSON schema 约束：非 OpenAI 模型需绕过校验（C8）
- 多供应商模型接入：OpenAI/OpenRouter/TogetherAI（C6）
- 云基础设施依赖：Postgres/Blob/Redis（C9）
- 模板继承型开源：Vercel ai-chatbot 基础（C17）
- 商业 API 锁定 + 已停止维护（C13、C14）
- 成本不透明：无单次成本/耗时数据（C16）

## opposing_to

- 与"自建抓取管道"流派方案可能对立：本文全部检索依赖 Firecrawl 商业 API（C2），自建爬虫/检索方案（如开源 crawler + 本地搜索）在供应商锁定、成本结构与可控性上与其立场相反
- 与"多源检索/多供应商检索器"方案可能对立：本文检索器唯一（Firecrawl），不支持 Tavily 等其他检索 API 切换（C2），而多源检索方案主张检索器可插拔
- 与"持续维护/活跃演进"方案可能对立：本文 2025-05-07 后无提交（C14），活跃项目在能力演进与依赖更新上与之不同
- 与"成本透明"型方案可能对立：本文无单次成本/耗时数据（C16），成本可测方案（如给出每次调研成本的实现）在可对比性上与其不同
- 与"自建全栈/原生应用"方案可能对立：本文深度研究逻辑叠加在 Vercel ai-chatbot 模板之上（C17），从零自研前端/持久化层方案在架构自主性上与之不同

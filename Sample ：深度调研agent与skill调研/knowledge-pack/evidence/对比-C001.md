### 3. 工作流维度（问题拆解 / 搜索规划 / 迭代检索 / 追问 / 报告组装）

- **GPT Researcher**：建 agent→生成问题→crawler 收集→摘要+来源追踪→聚合报告（S001 五步，官方声称）

- **STORM**：视角发现→模拟对话→信息策展→大纲→生成带引用全文（S003 pre-writing 创新重心）
- **hyperresearch**：16 步流水线（分层计划→检索→对抗性审查→引用验证→持久化）（S004）
- **ChatGPT DR**：异步多步研究，5-30 分钟（S005）
- **Perplexity DR**：迭代式研究，多数任务 <3 分钟（S006 官方声称）
- **Gemini DR**：Plan→Search→Read→Iterate→Output，通常 5-10 分钟（App）/20 分钟内（API 文档，口径差异已标注 S007）
- **Genspark**：未披露（登录墙）

## 共识

1. **多源检索 + 长报告生成 + 证据引用**是深度调研服务的公共能力基线（8 方案均声称具备，开源组有源码/文档佐证，付费组为官方声称）
2. **官方声称普遍缺乏独立第三方验证**：8 方案中 7 个（除 S002 部分源码级证据外）的性能/成本/评测数据均为官方自报；RACE/HLE/SimpleQA/GAIA 等基准分均需独立复测（对应 D003 验证任务）
3. **知识复用（长期记忆）是普遍缺口**：开源组仅 hyperresearch 有 vault，OpenDeepResearch 官方列为 open question；付费组均未披露
4. **成本披露两极分化**：开源工程驱动方案给出单次/评测成本估算（GPT Researcher ~$0.4/次、OpenDeepResearch $45-187/100任务、hyperresearch $60-120/查询），论文驱动（STORM）与付费侧（除 Gemini DR 外）成本不透明

## 分歧（各来源不一致处，注明持方）

1. **多 agent 有效性**：OpenDeepResearch 主张研究阶段 supervisor 多 agent 并行有效（S002，源码+官方第一手教训）；Cognition 博客反对多 agent 协作（S002 引用，待独立采集 SLD016）——已写入 A002 conflict_flags
2. **官方定位冲突**：GPT Researcher 官方自述"first open deep research agent"（S001），任务假设其为"OpenAI Deep Research 开源复刻"——定位冲突待合并员核验（S001 已标注）
3. **Gemini 官方内部矛盾**：发布文称支持 JSON schema 结构化输出 vs API 文档称不支持（S007）——已写入 A007 conflict_flags
4. **成本披露口径差异**：Gemini 官方文档 DR $1-3/任务 vs hyperresearch 官方称"超越商业服务"但成本 $60-120/查询（S004/S007，不同计量口径，客观记录）
5. **运行时间口径差异**：Perplexity 官方"多数任务 <3 分钟"（S006）vs Gemini App"5-10 分钟"/API"20 分钟内"（S007）——不同产品，时间口径不可比，须标注测试条件

## 综合判断（供知识管理员 ingest 的客观归纳，非立场结论）

- 生态呈现"开源工程驱动 / 开源论文驱动 / 付费商业托管"三组形态，能力基线趋同（多源检索+长报告+引用），差异集中在架构模式（多 agent vs 单 agent vs 流水线）、开放度（许可证/API/自托管）、成本披露透明度与知识复用能力
- 方法流派上，论文驱动（STORM）与工程驱动（GPT Researcher/OpenDeepResearch）构成开源组主要对比轴；多 agent vs 单 agent 是工程组内部流派分歧；人机协作（Co-STORM/hyperresearch）为新兴方向
- 证据质量上，开源组可复核（源码/README），付费组为营销声明——付费服务所有能力断言须经 D003/D007 独立验证后才能定置信度

# 需求发现

## 定位

需求发现是强场景策略，目标是从多类证据中识别真实需求、使用场景、痛点、雷区和指标映射。它可服务于产品选型、产品设计、用户研究、竞品分析和决策支持。

## source_strategy

优先组合：社区反馈、电商评价、售后投诉、官方参数、专业评测、问答平台、论坛、长测文章、标准/规范。

## extraction_questions

- 用户在什么场景下产生这个需求？
- 用户条件是什么？如空间、预算、技能水平、家庭/组织约束、风险承受能力。
- 需求是显性表达，还是从痛点/后悔/投诉中推断？
- 该功能是否真实有用？使用效果如何？
- 哪些问题是高频痛点？
- 哪些问题是购买后才发现的？
- 哪些雷区来自安装、售后、长期使用？
- 这个需求对应什么可验证指标？
- 哪些人适用，哪些人应排除？

## synthesis_dimensions

需求聚类、场景分层、用户条件、功能有效性、痛点频次、雷区类型、指标映射、可信度、适用/排除条件。

## knowledge_schema_seed

category / brand_model / user_scenario / user_condition / motivation / real_need / functional_need / positive_need / pain_point / pitfall / regret / installation_risk / service_risk / long_term_issue / reputation / metric / evidence / confidence / persona / exclusion

## saturation_rules

核心用户场景已覆盖；高频痛点收敛；功能需求能映射到指标；正向需求和负向雷区都有证据；适用人群和排除条件明确。

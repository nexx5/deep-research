# 产品选型

## 定位

产品选型是决策支持下的强场景策略。目标不是商品参数罗列，也不是直接比价，而是建立“选型原则库”：真实需求、场景条件、功能有效性、指标权重、雷区、排除条件和证据链。

## source_strategy

优先组合：

1. 官方参数：确定硬参数和声明。
2. 专业评测：验证性能、功能效果和横向差异。
3. 社区反馈：发现真实需求、长期问题、后悔点、雷区。
4. 电商评价：验证批量品控、物流、安装、短中期体验。
5. 售后投诉：识别低频但高损失风险。
6. 标准/规范：确定底线要求和安全/能效约束。
7. 价格历史：判断预算档位和购买时机。

## evidence_ranking

长期真实用户反馈与售后投诉揭示风险；专业实测验证性能；官方参数只作为声称；电商评价用于批量验证但需去噪；单条社区反馈不能直接作为结论。

## extraction_questions

- 这个品类的核心任务是什么？
- 用户在什么场景下使用？
- 用户条件是什么？如空间、预算、家庭/组织规模、安装条件、使用频率。
- 真实需求是什么，是否与购买动机一致？
- 哪些功能需求明确存在？哪些只是营销引导？
- 哪些功能实际效果好？证据来自哪里？
- 哪些功能看上去美好但长期使用一地鸡毛？
- 哪些指标是硬约束？哪些是加分项？哪些可降级？
- 高频痛点、购买后悔点、安装雷区、售后雷区分别是什么？
- 品牌/型号口碑是否稳定？是否有批次、地区或渠道差异？
- 这些发现如何映射成选型指标和排除条件？

## synthesis_dimensions

品类指标树、需求-场景映射、功能有效性、卖点验证、坑点聚类、品牌/型号口碑、预算分层、指标权重、排除条件、购买建议。

## knowledge_schema_seed

category / brand_model / user_scenario / user_condition / motivation / real_need / functional_need / positive_need / metric / marketing_claim / real_world_feedback / pain_point / pitfall / regret / installation_risk / service_risk / long_term_issue / reputation / tradeoff / budget_tier / selection_rule / exclusion / evidence

## saturation_rules

至少满足：

1. 核心用户场景和用户条件覆盖。
2. 品类指标树成型。
3. 每个关键指标有来源说明和可信度。
4. 正向需求、功能效果、高频痛点、负向雷区都有证据。
5. 官方卖点被专业评测、社区反馈或电商评价验证/证伪。
6. 安装、售后、长期使用问题已检查。
7. 品牌/型号口碑已区分事实、趋势和个案。
8. 能输出“适合谁、不适合谁、为什么选、为什么不选”。

# 采集

> 调研员子阶段：原始资料采集 + 引用追溯 + **取证分析（四问）**
> 本文件属于调研员，不独立调用。

## 硬规则

1. 搜索必须通过多源搜索skill执行（禁止直接webfetch猜URL）。论文搜索用学术引擎（arxiv/openalex），通用搜索用bing/searxng/baidu。搜索摘要不得作为原文记录的依据，必须通过多源搜索skill的正文提取通道取全文。
2. `read` 任何本地文件后必须同步写 raw-S{id}.md + 采集记录。
3. 引用 URL 必须追溯。未采过则追加一轮子采集。
4. 每条 raw 至少产生 **1 条延展线索**（对立面/前提争议/概念延展/盲区中的至少一个维度）。
5. 延展线索直接写入 `run-state.md` 的 `explore_keywords` 段（累加，不覆盖；**不写 project.config.md**——config 是静态定义，PLAN_REVIEW 后冻结）。

## 合规三级分级

采集和工具评估时，按以下三级分类处理，不再一刀切禁用：

### 违规禁用类（禁用，不采集不实现不推荐）

判定标准：
- 盗用、盗号、破解验证码
- 破坏性访问（DDoS、高频压垮服务器）
- 账号买卖

处理：禁止采集、禁止实现、禁止推荐。在分析中记录为"违规禁用"。

### 风控封禁类（可用但提示）

判定标准：
- 工具自承认会被封号/需用小号，但工程上可用（非"3次就失效"的极端不可用）
- Cookie 模拟、浏览器登录态复用、未授权 API 调用
- 有实际封号风险但有缓解措施（专用账号、限速、监控）

处理：可用，必须标注"封号风险提示"。在分析中记录风控缓解措施建议（专用账号、限速、监控、失败降级）。

### 提示类（不影响实现和使用，提示即可）

判定标准：
- 违反 robots.txt 协议但技术上可访问
- 违反 ToS 非核心条款但不影响数据获取
- 合规灰色地带（如搜索引擎索引内容的使用边界）

处理：可用，给出合规提示。在分析中记录合规提示但不阻断。

### 分级应用规则

1. 工具评估时，按三级分类标注，不再默认排除非官方工具
2. 同一工具的不同平台接入方式可能属于不同级别，需逐平台标注
3. 已有分析结论不回溯改写，但后续分析按新分级执行
4. 候选工具清单可包含"风控封禁类"和"提示类"工具，但必须标注级别和提示

## 策略加载

采集前必须读取 `project.config.md` 的 `research_type`、`research_subtype`、`strategy_tags`，并按需加载 `.opencode/research-strategies/types/`、`scenarios/`、`sources/` 中对应策略。

社区反馈、电商评价、售后投诉等策略标签即使当前 skill 抓取能力不足，也必须作为线索、死胡同或平台能力缺口记录，不得忽略。

## 并行派发

DISCOVER 默认拆成多个 sub-agent 并行执行，并行上限为 8。拆分维度包括关键词簇、来源类型、平台、竞品/对象、正反方向。每个 sub-agent 必须返回 raw、采集记录、死胡同或待采线索之一，禁止只返回搜索摘要。遇到工具失败、平台限流或连续抓取失败时，将并行上限降到 3 或串行。

## 流程

每轮对 focus_keywords 执行：

### C) 本地文件搜索（先做）

1. `grep` / `glob` 搜索 focus_keywords 在以下范围：
   - 本项目 `1-规划/` `04-参考资料/`（源材料文件，来源类型写"材料"）
   - 本项目 `01-采集记录/` `02-分析提取/` `03-知识提炼/`（过程文件，写"过程"）
   - 其他项目 `1-规划/` `04-参考资料/`（跨项目材料）
2. `qmd query "focus_keywords"` 补充语义匹配
3. 对未在 id_registry 中的文件：`read` 全文 → `raw-S{id}.md`（文件路径写完整）
4. 已注册的跳过

### A) 网络来源采集

调用 **[多源搜索] skill** 执行搜索与提取：

1. 按"搜索渠道决策树"并行启用引擎（Bing/SearXNG/Baidu 等）
   - **学术引擎启用条件**：`strategy_tags` 含 `academic`，或 `research_type` 为技术调研且涉及论文/算法/模型溯源时，必须在 `sources` 中加入 `arxiv`、`openalex`，按需加入 `semantic_scholar`
   - 学术引擎与通用引擎并行，不要只投学术引擎（博客/GitHub/技术文章靠通用引擎覆盖）
   - 学术引擎返回的论文摘要可直接作为 `content`，无需二次 webfetch 提取正文
   - 如需论文全文，使用返回的 `pdf_url` 下载 PDF（见步骤 a 的 PDF 处理）
2. 对返回的每个非重复 URL：
   a. 预检 URL：
   - 以 `.pdf` 结尾或学术引擎返回 `pdf_url` → 不调提取，直接下载 PDF 到 `01-采集记录/原始资料/assets/`，标记"PDF待提取"
   - 其他 → 按"提取渠道决策树"选择渠道（webfetch → web-fetch.cmd → CloakBrowser → CDP）取全文
     b. 全文存档 → `raw-S{id}.md`
   c. **学术论文特殊处理**：学术引擎返回的摘要（snippet/content）直接写入 raw 的摘要段；如有 `pdf_url`，下载 PDF 后用 opendataloader-pdf skill 提取全文，合并到 raw 中

**raw 写作规则（强制执行，不可绕过）**：

raw 文件必须是原文存档，不是摘要。规则：

1. web_fetch 返回的网页正文直接作为 raw 内容，不做任何"提炼要点"操作
2. 允许剪裁噪音（广告、导航、页脚），但不允许对正文做压缩、概括、改写
3. raw 文件长度应接近原始网页正文长度（通常 5-50KB，而非 0.3-2.5KB）
4. raw 必须保留原文中的以下内容，按项目类型检查：

**技术类 raw 保留检查清单**：

- CLI 命令块（```）、参数说明、使用示例
- 配置文件段（YAML/JSON/XML/INI）
- API 接口定义（endpoint、请求/响应结构）
- 架构描述（组件列表、交互关系、数据流）
- 性能 benchmark 数据（含测试条件）
- 实现细节（代码片段、算法、关键逻辑）

**非技术类 raw 保留检查清单**：

- 史料原文段落（史书/笔记/文集原文）
- 法令/诏书/制度条文原文
- 统计数据（原文数字+出处+统计范围）
- 人物直接引语（含上下文）
- 时间线（具体年月日+事件序列）
- 概念/术语的原文定义（文献出处+原文用词）

**每份 raw 存档后自检**：技术类检查 6 个维度，非技术类检查 6 个维度。合格维度 ≥ 4 才可进入下一步（写采集记录），不足则回退检查 web_fetch 结果是否完整；web_fetch 结果本身就不完整时，标记"原文不可及"。

### D) 线索发掘（强制，不可跳过）

> **这是采集阶段的核心增值环节，不是可选步骤。** 线索只写入 explore_keywords 而不生成 DISCOVER 任务 = 等于没发掘。subagent 必须同时产出线索清单和对应的 DISCOVER 任务建议。

每条 raw 采集完成后，必须从以下六类线索来源中发掘新线索。每条 raw **至少产出 1 条线索**，线索必须同时写入 explore_keywords **并生成对应的 DISCOVER 任务建议**（写入 subagent 返回值的 `discovered_leads` 字段）。

#### 线索来源矩阵

| 来源 | 动作 | 产出 |
|------|------|------|
| **D1 引用追溯** | 扫描 raw 中的外部 URL（arXiv/GitHub/论文/官网/原文/史料出处/档案编号），未采过的追加子采集 | DISCOVER 任务 |
| **D2 概念延展** | 文中提到的新概念/工具/人物/系统/制度/流派/术语，搜索其定义/对比/源流 | 搜索词 → explore_keywords + DISCOVER 任务 |
| **D3 对立面搜索** | 该观点的反对者/批判者/竞争理论/不同学派立场是什么 | 搜索词 → explore_keywords + DISCOVER 任务 |
| **D4 新观点追踪** | 文中提出了什么新观点/新诠释/新假说/新考据？无论是否被验证、是否可能错误，都是新内容，需追踪其证据链、支持者、反对者 | 搜索词 → explore_keywords + DISCOVER 任务 |
| **D5 关联实体** | 文中实体（工具/人物/事件/制度/作品/流派）的同类/竞品/上下游/前后承继关系 | 搜索词 → explore_keywords + DISCOVER 任务 |
| **D6 死胡同触发** | URL 403/timeout → 自动搜索替代源（镜像/Wayback/社区转载/其他版本） | DISCOVER 任务 |

#### 引用追溯特殊处理（D1）

1. 扫描新 raw / 本地文件中的引用 URL（arXiv/GitHub/论文/原文）
2. 未采过 → 追加子采集（回到 A 步），生成新 S{id}
3. 对 GitHub URL 特殊处理：
   a. `gh repo view <owner>/<repo> --json name,description,url` 取仓库基本信息
   b. `gh repo view <owner>/<repo> --readme` 取 README → 写 raw-S{id}（来源类型="GitHub README"）
   c. 不深度 clone，不做结构分析（交给分析阶段按需处理）
4. 不可访问 → 标记"引用不可及"，触发 D6 死胡同替代源搜索
5. **二手文章中的官方仓库链接必须追溯为一手来源单独采集**（如掘金文章引用了 GitHub 仓库，GitHub 仓库必须单独采为一个 S）

#### subagent 返回值结构（强制）

每个采集 subagent 返回时，除了 raw + 采集记录 + 分析外，必须包含 `discovered_leads` 字段：

```yaml
discovered_leads:
  - type: D1  # 引用追溯
    url: "https://github.com/xxx/yyy"
    reason: "文中引用的官方仓库/原始出处，一手来源"
    action: "采为独立S"
  - type: D2  # 概念延展
    keyword: "[新概念/术语/制度/流派名称]"
    reason: "新概念，需了解其定义、源流、与已知概念的关系"
    action: "搜索定义+源流+对比"
    → explore_keywords
  - type: D4  # 新观点追踪
    keyword: "[文中提出的新观点/新诠释/新假说]"
    reason: "新观点，需追踪其证据链、支持者、反对者"
    action: "搜索观点+证据+商榷"
    → explore_keywords
  - type: D5  # 关联实体
    keyword: "[实体A] vs [实体B] 对比/承继/竞争"
    reason: "同类/上下游/前后承继关系，需横向或纵向对比"
    action: "搜索关联分析"
    → explore_keywords
```

**未返回 discovered_leads 的 subagent 结果视为不合格，必须补做。**

### E) 取证分析 ← 核心

对每条新增 raw，从四个维度挖掘延展线索：

| 维度   | 要回答的问题                  | 产出                     |
| ---- | ----------------------- | ---------------------- |
| 对立面  | 该观点的反对者/批判者/竞争理论是什么？    | 搜索词 → explore_keywords + DISCOVER 任务 |
| 前提争议 | 该观点依赖的假设可靠吗？那个假设本身有无争议？ | 搜索词 → explore_keywords + DISCOVER 任务 |
| 概念延展 | 文中提到什么值得再挖的概念/案例/人物/系统？ | 搜索词 → explore_keywords + DISCOVER 任务 |
| 盲区   | 作者承认或未承认的局限是什么？         | 搜索词 → explore_keywords + DISCOVER 任务 |

每条 raw **至少产出 1 条**延展线索。线索追加到 `run-state.md` 的 `explore_keywords` 段（不覆盖，累加，**不写 project.config.md**），**同时生成对应的 DISCOVER 任务建议**。

### F) 关键词追加与收敛规则

> **采录分析后，基于新产出的内容自动生成搜索关键词，扩大下一轮搜索范围。** 这不是可选的——不追加关键词 = 线索只记录不行动 = 靠用户投喂。

#### 关键词追加流程

1. 每轮采集分析完成后，从该轮所有分析（A文件）的结论中提取新关键词
2. 关键词来源（按调研类型自适应，不限定技术类）：
   - 新实体名（工具/人物/事件/制度/作品/流派/机构）
   - 新概念/术语/观点/假说/诠释
   - 新对比维度/新关联关系
   - 新争议焦点/新证据
   - 新边界/限制/前提条件
3. 与已有 focus_keywords + 已追加关键词去重
4. 只保留与 research_axis.primary 相关的关键词，不相关的丢弃
5. 追加到 `run-state.md` 的 focus_keywords（不写 project.config.md）

#### 双维度四象限收敛规则

每轮结束后，从两个维度评估本轮产出：

- **质量趋势**（优劣）：跟上一轮比（趋势比较，不跟峰值比）
  - 优于：本轮产出质量高于上一轮
  - 劣于：本轮产出质量低于或等于上一轮
- **信息增量**（有无新）：跟知识图谱增量比
  - 有新：本轮给知识图谱增加了新节点/新边/新断言/或对现有断言的加强/反驳
  - 无新：本轮产出纯重复，无知识图谱增量

根据组合决定关键词和搜索动作：

| 组合 | 关键词动作 | 搜索动作 | 说明 |
|------|----------|---------|------|
| 优于 + 有新 | 增加/更新 | 继续 | 方向好且有增量，加速 |
| 优于 + 无新 | 增加/更新（换角度突破） | 继续 | 方向好但挖透了，换角度 |
| 劣于 + 有新 | 根据新内容增加/更新 | 继续 | 质量一般但有新发现，跟随新内容 |
| 劣于 + 无新 | 不更新，沿用上次 | 继续（等待其他线索） | 当前方向枯竭，等其他线索带来新方向 |
| **连续 2 轮劣于 + 无新** | — | **停止，该来源收敛** | 方向既差又空，判定收敛 |

#### 收敛后的处理

- 该来源（关键词组合）标记为收敛，不再生成新 DISCOVER 任务
- 其他来源（引用追溯/概念延展/对立面/工具关联/平台关联）仍可继续
- 所有来源都收敛 → 队列空 + 无缺口 + 无新线索 → CLOSED_LOOP saturated

## 来源元数据要求

每个 raw-S*.md 必须包含 `raw_metadata`。

每个采集记录-S*.md 或 采录-S*.md 必须包含 `canonical_source`。

### raw_metadata 最低要求

网页/论文/文档资料必须有：

- source_type
- title
- original_url
- captured_at
- display_citation

源码资料必须有：

- source_type: source_code
- repo_url
- local_repo_path
- files[].file_path
- display_citation

### canonical_source 最低要求

必须有：

- ref_id
- source_type
- title
- display_citation
- raw_ref

源码资料还必须有：

- repo
- file_path
- local_path

### 禁止

- 禁止把搜索摘要当 raw。
- 禁止把内部编号当 display_citation。
- 禁止 display_citation 写成 raw-S{id}、采录-S{id}、分析-A{id}。
- 如果原始URL缺失，必须写 `url_missing_reason` 或在采录质量记录中说明。

### 采录质量检查

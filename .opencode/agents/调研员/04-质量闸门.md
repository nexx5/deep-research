# 质量闸门

> 调研员子阶段：一手资料追溯 + 深度检查 + 知识包终验
> 本文件属于调研员，不独立调用。

> **【废弃声明 2026-08-06】**：平台只支持知识包模式（新协议项目），原批次模式（旧协议）已取消。本文件（04-质量闸门.md）是原批次模式子阶段定义，**不再作为调研员子阶段调用**（见 `agents/调研员/AGENTS.md`「子阶段调用」）。MapReduce 模式下，调研员在批次内直接执行跨源对比（C*）与质量验证（见自治循环步骤 6），质量检查标准以本文件所述维度为参考（一手追溯/深度检查/终验），但不再作为独立子阶段文件被调度。

## 策略加载

质量检查前必须读取 `.opencode/research-strategies/types/`、`scenarios/`、`sources/` 中对应策略，使用其中的 `evidence_ranking` 和 `quality_rules` 修正来源分级与证据强度判断。

## 闸门一：一手资料追溯

对每个待写入的条目追溯信息源头：

| 来源类型 | 处理 |
|---|---|
| 一手资料直接产出（论文原文/官方文档/源代码/arXiv PDF） | → 直接进入闸门二 |
| 二手解读（公众号/博客/综述/教程），一手可获取 | → 先读一手资料全文，基于一手资料重分析，再进入闸门二 |
| 二手解读，一手不可获取 | → 允许写入，来源标注 `"基于二手资料，一手不可及"` |

**可获取性判断**：arXiv PDF 始终可获取；开放获取论文 HTML 可获取；付费论文有摘要页也可获取摘要；链接失效/引用模糊不足定位 → 不可获取。

## 闸门二：分类 → 检查 → 价值评估 → 补全状态

### Step A — 条目分类

六类：理念 / 实践 / 体系 / 史实 / 观点 / 素材

### Step B — 类别感知字段检查

按类别确定最低字段要求：

```
理念/史实/观点（核心要求较轻）：
  "深度解析": { "核心问题", "内在逻辑" }
  可选：关键要素、边界条件、替代方案、后续影响

实践（要求较重，必须说清机制和边界）：
  "深度解析": { "核心问题", "内在逻辑", "关键要素", "边界条件" }
  "所处位置": { "前置依赖", "关联关系", "替代方案", "后续影响" }

体系：同时满足理念类和实践类全部字段

素材（最低要求）：
  "初步判断": "这条信息的初步印象"
  "待处理": "归类/深挖/甄别"
```

### Step C — 调研价值评估

关键/高/中/低。不同类别可同等价值。

### Step D — 补全状态判定

| 状态 | 条件 | 处理 |
|---|---|---|
| 已完成 | 核心字段全部可填 | → 写入知识包 |
| 待补全 | 核心字段可填，部分非核心缺 | → 写入知识包，标记缺哪些字段 |
| 待深挖 | 核心字段信息不足 | → 不写入，针对性深挖后回到采集阶段 |

**补充规则**：
- 素材类始终为"待补全"——写入并标记"待加工"
- 一手不可及的条目允许以已有信息填写
- 所有"待补全"条目在终验时集中检视

## 终验

### 资料分级

对单篇原始资料评估：

```
评估维度：
  来源权威性:  官方文档 > 行业报告 > 深度分析 > 一般博客 > 论坛
  信息密度:    高 / 中 / 低
  时效性:      发布时间距今是否仍有参考价值
  客观程度:    事实数据 > 分析推论 > 主观观点
  交叉验证:    是否有独立来源佐证

综合输出等级：
  A 级: 官方文档/白皮书/一手数据 → 必入调研资料库
  B 级: 深度分析/行业报告         → 入调研资料库
  C 级: 一般文章/博客             → 视相关性
  D 级: 低质/水文                 → 标记后不入库
```

### 矛盾检测

对调研资料库中覆盖同一主题的多篇资料：

1. 提取各篇资料中的关键结论
2. 对比结论域重叠部分
3. 不一致时标记为矛盾
4. 判断矛盾来源：样本差异 / 时间差 / 角度不同 / 真冲突
5. 对每个矛盾，评估哪个结论证据更强

### 置信度评分

对每条结论：

```
置信度 = f(验证次数, 独立来源数, 来源权威性)

High:   ≥3 个独立来源，其中至少 1 个 A 级，结论一致
Medium: 2 个独立来源，或 1 个 A 级 + 其他非矛盾来源
Low:    单来源，或矛盾未解决
```

### 盲区声明

列出确定无法回答的问题：
- 无可用数据
- 数据相互矛盾难以判定
- 超出了当前采集范围

### 终验动作

- 矛盾检测 → 置信度评分 → 盲区声明
- 扫描"待补全"条目：价值为"关键/高" → 发起补挖；"中/低" → 标注知识缺口
- 扫描"待深挖"条目：是否因一手资料不可及 → 如是则转入"待补全"

## 技术报告就绪度检查（终验子步骤）

**触发条件**：仅当下一阶段需要出具技术报告时执行。其他报告类型跳过。

**检查方法**：遍历 raw 文件，按项目类型检查：

技术类项目检查 6 个维度：CLI/命令、配置、API/接口、架构、性能数据、实现细节

非技术类项目检查 6 个维度：史料原文、法令条文、统计数据、人物引语、时间线、概念原文

**评分标准**：每通过 1 个维度得 1 分，满分 6 分。

| 分数 | 判定 | 处理 |
|---|---|---|
| ≥ 5 分 | ✅ 就绪 | 可出技术报告 |
| 3-4 分 | ⚠️ 基本就绪 | 可出技术报告，附维度缺口声明 |
| ≤ 2 分 | ❌ 未就绪 | 阻止出技术报告，启动补采 |

**判定基准**：取全部 raw 文件得分的**中位数**（而非平均值，避免个别好文件拉高整体）。
